# Codex goal prompt

Run this from the repository directory after the baseline direction has co-lead approval.

```text
/goal Complete the public “C++ in Quant Finance” workshop without stopping until the HTML presentation and all six C++ checkpoints form a coherent, beginner-tested 105-minute teaching experience. Read README.md, the current HTML/CSS/JS deck, and every file in checkpoints/ before changing anything. Preserve the agreed 15/10/70/10 structure, Buy/Sell teaching vocabulary, simple hand-drawn academic-notebook visual direction, GitHub-to-CoderPad workflow, and the rule that cancellation remains an open-ended extension. Do not add unrelated finance topics, a framework, external runtime dependencies, copied third-party visuals, or advanced iterator-indexed cancellation to the core.

Work in reviewable checkpoints. Keep a short progress log in PROGRESS.md. For every implementation checkpoint, provide a starter that compiles, visible behaviour-based tests, a completed catch-up version, and concise teaching notes. Validate all completed C++ files with a current C++ compiler, validate the HTML and JavaScript, run the deck locally, and visually inspect representative opening, order-book, code, and closing slides at 16:9 and a narrow viewport. Keep the repository clearly marked as in development until all placeholders are resolved.

Stop only when: the deck covers the approved narrative end-to-end; all six checkpoints and solutions exist and pass; slide-to-checkpoint links are correct; keyboard navigation, fullscreen, reduced motion, print layout, and mobile fallback work; credits and public-facing copy are accurate; no presenter or contact placeholders remain; and README.md contains complete workshop-day and contributor instructions. If progress is blocked by a content decision that would materially change the workshop, record the exact decision in PROGRESS.md and continue every independent task before reporting the blocker.
```

This follows the official `/goal` pattern: one durable objective, explicit constraints, validation evidence, checkpointed progress, and a verifiable stopping condition.
